# 2026-11-25 · Федотов · GigaChat и YandexGPT в LLM-шлюзе

**Зона:** красная (ключи доступа и данные, которые уходят во внешний сервис) и жёлтая (обработка
ответов). Обезличивание перед отправкой делает шлюз — его этот пулл-реквест не меняет.

**Задача.** Неделя 3 плана: подключить GigaChat и YandexGPT к шлюзу вместо заглушек.

**Что предложил ИИ:**
- токен GigaChat хранить и обновлять за минуту до конца срока (живёт 30 минут), при ответе 401 —
  один повтор с новым токеном;
- любой непонятный ответ провайдера считать «провайдер молчит», чтобы шлюз переходил к запасному (Р-4);
- считать потраченные токены у каждого провайдера — так закроем задачу «сколько токенов на резюме» (Р-5);
- разбор ответов проверять тестами без сети, а сами запросы — на поддельном HTTP.

**Что решили сами и почему:**
- Ключи только в `.env` на стенде. Без ключа провайдер просто не подключается, а не падает:
  карта строится без пояснений, навыки ищутся по словарю.
- Адреса API вынесли в настройки: у GigaChat с июля 2026 новый адрес `api.giga.chat`, у Yandex
  в документации встречаются два адреса — если один не ответит, поменяем в `.env` без нового кода.
- Температуру поставили низкую (0,2): нам нужна аккуратность, а не фантазия (Р-3).

**Что проверил человек (без этого не сливаем):**
- [ ] С настоящим ключом GigaChat (через вуз) запрос проходит; если ошибка сертификата — указал путь к сертификату Минцифры в `GIGACHAT_CA_BUNDLE`
- [ ] В `.env` ключи есть, в репозитории — нет (`git grep -i "api_key="` пустой, кроме `.env.example`)
- [ ] Выключил интернет — карта всё равно строится (запасной путь)
- [ ] `ruff check .`, `mypy`, `pytest` — зелёные в CI

**Известные ограничения:** с настоящими серверами не проверено — ключей пока нет. Формат запросов взят
из документации Сбера и Yandex Cloud.
