# Эталонный набор (golden set)

Набор нужен для двух проверок:

1. **Разбор резюме** (неделя 3, TC-02): сравниваем навыки, которые нашла программа, с навыками,
   которые человек отметил вручную. Порог — точность не ниже 80% (риск Р-6).
2. **Построение карты** (спринт 3, TC-08): по одним и тем же навыкам карта не должна «поехать»
   после изменений в коде.

Все id навыков и профессий берём **только из справочника**
`backend/app/modules/catalog/data/catalog.json`. Тест `tests/test_golden_set.py` проверяет это
на каждом пулл-реквесте, так что опечатку в id CI не пропустит.

## Резюме с ручной разметкой — `resume_XX.txt` + `resume_XX.json`

Резюме — только настоящие, от знакомых студентов, с их согласия. Придуманные резюме не годятся:
по ним мы проверили бы сами себя, а не программу.

Перед тем как положить файл сюда, из текста убираем ФИО, почту, телефон, ссылки на соцсети
и GitHub. Тест ищет в `.txt` почту и телефон и падает, если найдёт.

`resume_01.txt` — обезличенный текст резюме как есть.

`resume_01.json` — что в нём нашёл человек:

```json
{
  "profession_id": "backend-junior",
  "skills": ["python", "git", "sql"],
  "comment": "Django упомянут только в курсе, без проекта — не засчитываем"
}
```

Правила разметки, чтобы два человека размечали одинаково:

- навык засчитываем, если он есть в проекте, на работе или в стажировке; одно слово в списке
  «Навыки» без примеров — тоже засчитываем, программа поступит так же;
- навык, которого нет в справочнике (например, Kotlin), не размечаем;
- спорные случаи пишем в `comment`, чтобы потом обсудить на ретро.

## Случаи для карты — `case_XX.json`

```json
{
  "profession_id": "backend-junior",
  "skills": ["python", "git"],
  "expected_steps": ["linux", "oop", "sql", "http-api", "web-framework", "testing", "docker", "team-project"]
}
```

`expected_steps` — недостающие шаги карты по порядку. Карту для каждого случая собирает вручную
Никита, по справочнику, а не копирует из программы.

Важно: никаких имён, почты и телефонов. Только текст про учёбу, проекты и навыки.

## Как замерить точность

Из папки `backend`:

```bash
python -m app.tools.eval_golden_set          # только словарь
python -m app.tools.eval_golden_set --llm    # LLM со словарём, нужны ключи в .env
```

Скрипт покажет по каждому резюме, что нашлось лишнего и что пропущено, итоговые точность и полноту,
а с `--llm` — сколько токенов уходит на одно резюме (риск Р-5). Если точность ниже 80%,
скрипт завершается с ошибкой: это ранний сигнал риска Р-6, результат пишем в дневник.
